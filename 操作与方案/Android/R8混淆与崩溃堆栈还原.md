# R8 混淆与崩溃堆栈还原

发布构建启用 R8 后，如何判断哪些代码需要保留，以及如何还原混淆的崩溃堆栈？前者发生在构建前，靠保留规则约束 R8；后者发生在构建后，靠该次构建的映射解释堆栈。

## ProGuard 与 R8 的关系

Android Gradle Plugin（AGP）3.4.0 起默认使用 R8 处理启用收缩的 Android 构建。R8 支持 ProGuard 格式的保留规则，因此项目中仍常见 `proguard-rules.pro` 等文件名。原摘录所说的四步来自 ProGuard 手册，其中 Preverify 为特定 Java 目标的 class 文件写入预校验信息。Android 的 R8 构建应按 AGP 文档理解，无需配置一个单独的 Preverify 步骤。依据 [AGP 3.4.0 发布说明](https://developer.android.com/build/releases/agp-3-4-0-release-notes)和 [ProGuard 手册](https://www.guardsquare.com/manual/home)。

- **收缩（shrink）**移除 R8 判定不可达且规则允许移除的类和成员。
- **优化（optimize）**改写代码，例如内联方法、简化指令。
- **混淆（obfuscate）**缩短类和成员的名称，以减小产物体积。名称变短也会增加人工阅读难度，应用内数据和逻辑的安全仍要靠相应的安全机制。

以上是代码优化的作用。开启资源收缩后，构建也可以移除未用的 Android 资源。详见 [Android Developers 的 R8 启用指南](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization)。

## 启用优化与收窄保留规则

1. **先确认应用模块的 AGP 版本和发布变体。** 常见的 Kotlin 旧 DSL 用 `isMinifyEnabled = true` 开启代码优化，用 `isShrinkResources = true` 开启资源收缩，并通过 `proguardFiles` 配置规则。AGP 9.3 起官方文档提供 `optimization { enable = true }`，一次开启两类优化并带入默认 Android 规则；使用该 DSL 时，自定义规则放入对应源集的 `keepRules` 目录，使用 `.keep` 后缀。AGP 8.0 起 full mode 默认启用，是否优化某个变体仍需检查该变体的设置。见 [启用方式与版本表](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization)。
2. **从动态访问实际依赖的契约着手。** 先查框架或库是否已携带 consumer rules，再看项目里的反射、原生代码经 JNI 按名称查找 Java/Kotlin 成员，以及依赖运行时注解或泛型签名的序列化。定位到具体调用后，分别确认它依赖类或成员仍存在、名称不变，还是特定属性仍存在。把规则限定在实际依赖的类、成员和属性。见 [保留规则概览](https://developer.android.com/topic/performance/app-optimization/keep-rules-overview)与 [规则写法](https://developer.android.com/topic/performance/app-optimization/add-keep-rules)。
3. **从可回归的基线逐步收窄。** 先用启用了优化的实际发布变体验证关键路径，每次调整一组规则后复跑对应场景。优化后出现 `ClassNotFoundException` 等错误时，先核对该类是否随包交付，以及动态调用点依赖的类、成员或名称，再决定补哪条规则。具体项目的规则需随依赖版本和发布构建核对。见 [排查 R8 优化问题](https://developer.android.com/topic/performance/app-optimization/troubleshoot-the-optimization)。

## 用同一次构建的映射还原堆栈

发布时按版本、变体和构建标识归档 `mapping.txt`。AGP 的映射输出位于应用模块的 `build/outputs/mapping/` 下，后续构建会覆盖旧文件。收到崩溃堆栈时，先确认出问题的产物对应哪次构建，再向 Android SDK 命令行工具中的 `retrace` 提供那次构建的映射和堆栈文本。按其输出定位原始类、方法和可用的行号信息。缺少对应映射时，先查发布归档或原 AAB。R8 retrace 处理的是堆栈符号，已裁剪的代码仍需通过调整规则并重新构建才能回到产物。见 [R8 retrace 用法](https://developer.android.com/tools/retrace)与 [映射文件说明](https://developer.android.com/topic/performance/app-optimization/troubleshoot-the-optimization)。
