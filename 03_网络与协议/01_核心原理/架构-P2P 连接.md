#信令 #通信 

P2P **全称** Peer-to-Peer，中文译文 **点对点** 或 **对等网络**。

参与通信的双方或多方地位对等，**直接互相连接和交换数据**，而不是必须通过中心服务器中转。
	服务器**不做**：传数据。**做**：帮助双方 认识 和 找路 。

**P2P 连接 = 地址发现 + 打洞 + 协商 + 加密 + 失败时中继**

**定位** 一种应用层的**对等网络架构**：让节点之间尽可能直接通信；中心服务器退居为发现、信令、协调和保底中继，而不是业务数据的必经之路。“中心化互联网的补充架构”，让中心服务器从“数据中转站”降级到“介绍人、协调者和保底中继”，让端与端尽量直连。

**优势** 低延迟、省服务器带宽、隐私更好。

**难点** 双方在 NAT/防火墙后面，彼此不知道对方公网地址，不能随便被主动连接。

#### 1、P2P 节点

被称做 servent = server + client。即每个节点既是客户端也是服务端。

它既消费资源，也贡献资源：带宽、存储、算力、内容。

#### 2、价值

- 降低服务器带宽和成本
- 降低延迟，尤其是同地域直连
- 可扩展：节点越多，资源越多
- 隐私和抗审查：数据不经过中心
- 容错：没有单一中心瓶颈

#### 3、代价与边界

- NAT/防火墙穿透复杂，对称 NAT 常需 TURN 中继。
- 节点发现、信任、安全、审计更难。
- 移动网络、弱终端、强一致性场景不适合纯P2P。
- 可能暴露IP，存在隐私和合规问题。

#### 4、应用定位

典型场景：BitTorrent、WebRTC 音视频/数据、区块链、IPFS、去中心化存储、游戏联机、IM、P2P CDN。
