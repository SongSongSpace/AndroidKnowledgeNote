#技术栈/WebRTC #状态/未完成 

## 1. 问题现象

采集端设备没有声音：系统内部声音无、外部麦克风声音也无。但接收端浏览器仍可能听到刺耳音频。

## 2. 结论先行

**有可能，但不是必然。**  
关键看采集端“无声”时，采集到的是**纯数字静音（全零）**，还是**带底噪的静音**。

- 纯数字静音：增益再高也是零，接收端无声。
    
- 带底噪静音：AGC 或手动增益过高，会放大底噪；严重时削波，产生高频谐波，接收端听到刺耳、破音、尖锐失真。
    

## 3. 根因链路

1. **“无声”不等于“零信号”**  
    麦克风、声卡、系统内录 loopback 即使没人说话，也常有本底噪声、电路噪声、量化噪声。
    
2. **WebRTC AGC 会泵升增益**  
    WebRTC 音频处理模块 APM 含自动增益控制 AGC。静音时它误判音量太低，持续拉高增益。内部还涉及 `pre_gain`、模拟麦克风增益、`post_gain` 等多层调节。
    
3. **高增益导致底噪被放大**  
    底噪接近满幅时发生削波，产生大量高频谐波，听感从“沙沙声”变成“刺耳失真”。
    
4. **系统内录要看采集源**  
    多数系统内录无播放时是纯数字静音；但立体声混音、loopback 源可能仍有底噪，也会被放大。
    
5. **完全无输入则通常不会**  
    硬静音、麦克风未连接、权限拒绝、无音频轨道时，没有有效音频发送，接收端一般不会刺耳。
    
6. **其他刺耳原因**  
    声学啸叫、采样率不匹配、缓冲区欠载、编解码异常、接收端音量过大、降噪/回声消除在极端增益下的 artifacts。
    

## 4. 排查清单

1. 采集端用 `AnalyserNode` 查看 RMS 和频谱，确认静音时是否有底噪。
    
2. 检查操作系统麦克风增强是否开启，如 +20dB/+30dB。
    
3. 查看 `getUserMedia` 约束，确认 `autoGainControl` 是否开启。
    
4. 检查是否手动使用 `GainNode` 或 SDK 接口加了增益。
    
5. 确认系统内录源是纯数字静音，还是带底噪的 loopback。
    
6. 接收端监听原始流，判断噪声频率、是否削波、是否啸叫。
    

## 5. 规避与修复

- 不需要 AGC 时关闭：
    
    js
    
    audio: {
      autoGainControl: false,
      noiseSuppression: true,
      echoCancellation: true
    }
    
- 手动增益设上限，发送前加限幅器或动态压缩。
    
- 加噪声门：低于阈值直接送静音。
    
- 关闭系统麦克风增强，换用干净采集源。
    
- 接收端音量不要过大，排除扬声器回采啸叫。
    
- 若确认是纯数字静音，可忽略；若有底噪，优先降增益、开降噪。
