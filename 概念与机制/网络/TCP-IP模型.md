# TCP/IP 模型

#网络通信 #状态/已完成

发给其他网络的服务时，为什么以太网帧的目的 MAC 指向网关，IP 包里的目的地址却是服务器？从应用到链路，每层处理的对象和交付范围不同。

## 四层和五层读法

RFC 1122 §1.1.3 从上到下列出应用层、传输层、互联网层和链路层。对照 [[概念与机制/网络/OSI模型|OSI 模型]] 时，可以按职责近似理解：

- **应用层**涵盖应用协议及其用到的表示和会话功能，如 HTTP、DNS。这些功能可以由不同协议或软件组件实现。
- **传输层**如 TCP 和 UDP。源、目的端口属于具体传输协议，用于区分通信端点。IP 地址用于网络交付，端口帮助主机把数据交给对应的传输端点。
- **互联网层**大致对应 OSI 网络层。IP 提供跨网络寻址与分组交付，路由决定所用的下一跳。
- **链路层**负责怎么在当前网络上发送和接收。教学中常用的五层读法把这一部分展开为数据链路层和物理层，便于分别说明帧与信号。两种读法可以用来解释同一条通信路径。

## 下一跳与地址解析

以客户端通过以太网访问另一网络的 TCP 服务为例。假设路由把流量交给网关，且不经过 NAT：

1. TCP 段带有客户端源端口和服务目的端口。IP 包携带客户端与服务器的 IP 地址。
2. 客户端查询路由，得到下一跳网关及出接口。若没有可用的缓存项，客户端在本链路发送 ARP 请求，用**下一跳的 IPv4 地址**查询其链路层地址。
3. 客户端把 IP 包封装进以太网帧，帧的目的 MAC 是网关接口的 MAC，包的目的 IP 仍是服务器。经过路由器转发时，出链路使用该跳所需的封装。
4. 若路由选出的目标就在本链路，下一跳即目标本身，此时解析的是目标的 IPv4 地址。IPv6 在需要解析本链路邻居地址时使用 ICMPv6 邻居发现（Neighbor Discovery）。

这是用于对照各层职责的示意路径。若要继续看地址转换与直连，从 [[导航/网络与连接|网络与连接]] 进入 NAT 和 P2P 路线。
